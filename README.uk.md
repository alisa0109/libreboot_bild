# T440p Libreboot Builder (Українська інструкція)

Автоматизований інструмент збірки прошивки [Libreboot](https://libreboot.org)
для **Lenovo ThinkPad T440p**. Він тільки збирає і перевіряє ROM. Він
**ніколи не пише в SPI flash** — прошивання це окремий, свідомий, ручний
крок, який ти робиш сам після перевірки готового файлу.

*(English version: [README.md](README.md))*

## 1. Що робить скрипт, по кроках

1. Перевіряє твою ОС/архітектуру та залежності.
2. Перевіряє 4 файли дампу BIOS, які ти надаєш (розмір, збіг хешів двох
   копій, структурна перевірка).
3. Об'єднує перевірені дампи і звіряє layout флеш-пам'яті T440p.
4. Клонує реальний `lbmk` (система збірки Libreboot) і збирає ціль для
   T440p з payload GRUB2.
5. Встановлює твоє фонове зображення GRUB та налаштування конфігу.
6. Перевіряє готовий ROM (розмір, вміст CBFS, Intel Flash Descriptor, що
   файл не "порожній") і розбиває його на два файли під розмір реальних
   чипів, які потрібні для прошивання.
7. Записує `output/BUILD-REPORT.txt` і зупиняється — нічого не прошиває.

Будь-яка провалена перевірка зупиняє весь процес. Краще зупинити збірку,
ніж видати ROM, у якому інструмент не впевнений.

## 2. Підтримувані системи

Ubuntu LTS або Debian (stable/testing), x86_64, Bash 5+, Python 3.
`./build.sh` сам перевіряє це і відмовляється працювати деінде.

## 3. Встановлення залежностей

Цей інструмент **ніколи сам не виконує** `apt install` — він тільки друкує
точну команду. Запусти:

```
./build.sh --check
```

Він покаже два блоки пакетів, якщо чогось не вистачає:

- **Залежності самого скрипта** (git, python3, sha256sum тощо) —
  встановлюються командою `apt-get install`, яку він надрукує.
- **Залежності збірки libreboot** — інструмент читає їх напряму з
  клонованого репозиторію `lbmk` (файл `config/dependencies/debian` або
  `ubuntu`), тож ти отримуєш точно те, що потрібно реальній збірці —
  ту саму команду `sudo apt-get install --no-install-recommends ...`,
  яку `lbmk` виконав би сам через `./mk dependencies debian`.

## 4. Куди класти дампи BIOS

У T440p **два фізичні SPI flash-чипи**: 8 MiB під нижньою кришкою
(низький діапазон адрес, містить Intel Flash Descriptor) і 4 MiB під
маленькими дверцятами (високий діапазон адрес). Офіційний гайд Libreboot
по SPI рекомендує зчитувати кожен чип **двічі** й звіряти хеші — саме це
й перевіряє інструмент.

Поклади чотири файли в `dumps/`:

```
dumps/upper_1.bin   4 MiB (4194304 байт)  -- чип під дверцятами, зчитування №1
dumps/upper_2.bin   4 MiB (4194304 байт)  -- чип під дверцятами, зчитування №2
dumps/lower_1.bin   8 MiB (8388608 байт)  -- чип під нижньою кришкою, зчитування №1
dumps/lower_2.bin   8 MiB (8388608 байт)  -- чип під нижньою кришкою, зчитування №2
```

`upper_1` має бути побайтово ідентичним `upper_2`, а `lower_1` — `lower_2`.
Якщо вони не збігаються, інструмент зупиняється і повідомляє, яка пара не
збіглася — перечитай той чип ще раз.

`dumps/` ніколи не змінюється цим інструментом. Уся робота відбувається на
копіях у `work/`.

## 5. Що насправді доводить подвійна перевірка дампів

Збіг SHA256 між двома зчитуваннями доводить лише, що ці два зчитування
ідентичні *одне одному* — але нічого не каже про те, чи є хоч одне з них
справжнім BIOS-образом (теоретично обидва можуть бути однаково поганим
зчитуванням). Після перевірки хешів `tools/verify_dump.py` додатково
перевіряє, що дані не "порожні"/вироджені (не більше 99% файлу — це один
повторюваний байт, широка гістограма значень байтів), а для LOWER-дампу —
що на очікуваному зсуві є валідна сигнатура Intel Flash Descriptor.

## 6. Додавання фону GRUB

Поклади PNG або JPEG у `assets/grub-background.png` (назва файлу
налаштовується через `GRUB_BACKGROUND` у `config/t440p.conf`). Інструмент
сам масштабує/конвертує зображення точно до 1280x800, 8-біт палітра PNG —
саме такий формат і роздільність використовує дефолтний фон Libreboot — і
встановлює його в клонований репозиторій перед збіркою. Після збірки він
перевіряє через `cbfstool`, що `background.png` дійсно потрапив у CBFS
готового ROM.

## 7. Пробний прогін (dry run)

```
./build.sh --check
```

Перевіряє ОС, залежності, дампи (розміри/хеші/структуру), клонує й
перевіряє джерело libreboot, підтверджує, що ціль збірки для T440p досі
існує, і перевіряє/конвертує фонове зображення. Нічого не створює в
`output/`.

## 8. Повна збірка

```
./build.sh --auto
```

або просто `./build.sh` без аргументів (те саме, після виводу банера
меню). Перший запуск компілює повний крос-компілятор для coreboot і може
зайняти багато часу й дискового простору — це нормально для будь-якої
збірки coreboot/libreboot, на будь-якій машині.

## 9. Де опиниться готовий ROM

```
output/t440p-libreboot.rom              12 MiB, повний образ (для звірки/хешу)
output/t440p-libreboot-spi1-8mb.rom     прошити в 8 MiB чип під нижньою кришкою
output/t440p-libreboot-spi2-4mb.rom     прошити в 4 MiB чип під дверцятами
output/*.sha256                         контрольна сума для кожного файлу вище
output/BUILD-REPORT.txt                 повний звіт про збірку
```

## 10. Перевірка SHA256

```
cd output
sha256sum -c t440p-libreboot.rom.sha256
sha256sum -c t440p-libreboot-spi1-8mb.rom.sha256
sha256sum -c t440p-libreboot-spi2-4mb.rom.sha256
```

## 11. Якщо щось не вдалося

Інструмент друкує кольоровий блок `[ ERROR ]`, який пояснює, яка саме
перевірка провалилась і чому, а весь прогін логується у
`logs/build-<timestamp>.log`. Він ніколи не виведе "BUILD SUCCESSFUL",
якщо не пройшла хоч одна перевірка. Типові причини: пара дампів не
збігається (поганий SPI-контакт — перечитай той чип), неправильний розмір
дампу (не той чип або обірване зчитування), відсутні залежності (див.
пункт 3), або справжня помилка збірки всередині lbmk/coreboot (дивись
лог — реальна причина зазвичай в останніх ~20 рядках виводу збірки).

## 12. Прошивання (свідомо поза межами цього інструмента)

Цей інструмент лише створює й перевіряє `output/*.rom`. Він ніколи не
викликає `flashrom`/`flashprog` для запису. Прошивання внутрішнього
образу на материнську плату ноутбука несе реальний ризик перетворити його
на цеглину, якщо зробити щось не так — спочатку перевір ROM сам (пункт
10), потім дотримуйся офіційного гайду Libreboot по прошиванню T440p
зовнішнім програматором, щоб записати `t440p-libreboot-spi1-8mb.rom` і
`t440p-libreboot-spi2-4mb.rom` у відповідні чипи.

## Обґрунтовано реальним кодом Libreboot (чому інструмент влаштований саме так)

Оригінальне технічне завдання для цього інструменту припускало кілька
речей про Libreboot, які після перевірки за реальним кодом `lbmk` та
документацією coreboot для цієї плати виявилися не зовсім точними. Цей
інструмент реалізує реальні механізми, а не припущені:

- **Wi-Fi whitelist.** У `lbmk` немає жодної команди `./mk`, прапорця
  збірки чи бінарного патчу, який "видаляє" Wi-Fi whitelist Lenovo, тому
  що whitelist — це код всередині пропрієтарного BIOS Lenovo. Libreboot
  повністю замінює цю прошивку, тож цього коду просто немає в результаті.
  `lib/whitelist.sh` перевіряє, що зібраний ROM — це справжня збірка
  coreboot (а отже, за визначенням, без цього коду), замість того щоб
  імітувати "патч", якого не існує в апстрімі.
- **Файли постачальника (ME/GbE/descriptor).** `lbmk` постачає для цієї
  плати шаблон Intel Flash Descriptor + GbE, який можна вільно
  розповсюджувати (`config/ifd/t440p/{ifd,gbe}`), і завантажує Intel ME
  напряму з офіційного сервера оновлень Lenovo під час збірки
  (`config/vendor/haswell/pkg.cfg`, з хешем, зафіксованим у цьому ж
  файлі). Тобто звичайний `./mk -b coreboot t440plibremrc_12mb` вже сам
  по собі дає повний, придатний до прошивання ROM. Твої дампи
  використовуються для того, щоб зберегти **твою власну оригінальну
  MAC-адресу GbE** в результаті (`lib/libreboot.sh
  inject_original_mac`, за тим самим механізмом `nvmutil`+`ifdtool`, який
  документовано використовує сам `lbmk`) — це персоналізація, а не вимога
  для збірки.
- **Layout флеш-пам'яті.** У T440p два фізично різні чипи (8 MiB на
  низьких адресах / 4 MiB на високих), що підтверджено документацією
  `doc.coreboot.org/mainboard/lenovo/t440p.html` та офіційним гайдом
  встановлення Libreboot для T440p, який розбиває об'єднаний образ так
  само, як і цей інструмент (`dd bs=1M count=8` / `dd bs=1M skip=8`).
- **Назви цілей збірки** (`t440plibremrc_12mb`,
  `t440plibremrc_4mcbfs_12mb`) і кожен виклик `./mk` у цьому проєкті
  зчитані напряму з клонованого репозиторію (`include/*.sh` та
  `config/coreboot/`) — а не вгадані з тексту документації. `./mk -b
  coreboot list` (буквально `ls -1 config/coreboot` всередині `lbmk`)
  використовується під час виконання, щоб підтвердити, що ціль досі
  існує, а не покладатися на захардкоджену назву.

Джерела: `libreboot.org/docs/install/t440p_external.html`,
`libreboot.org/docs/install/spi.html`, `libreboot.org/docs/build/`,
`doc.coreboot.org/mainboard/lenovo/t440p.html`, і сам код `lbmk` на
`codeberg.org/libreboot/lbmk`.
